## Which AI tools I used

- **Claude Code** (Anthropic's agentic CLI/desktop tool, running the Claude Fable 5.1 model). It was given the take-home brief (`.docx`) and asked to build the solution.
- No other AI tools were used.

## What I used AI for

- **Reading the brief and turning it into a design**: mapping the four required edge cases (duplicate bookings, overbooking, payment failure, last-seat race) to concrete mechanisms, and deciding which check belongs in the UI, the service, the database, or a background job.
- **Choosing the stack**: Node.js + TypeScript with the built-in `node:sqlite` and no runtime dependencies, so the reviewer can run it with `npm start` and nothing to install.
- **Writing the implementation**: schema (partial unique index + capacity triggers), the booking service, the small HTTP layer, the two pages, the seed data.
- **Writing the tests**: including a payment-provider test double whose charges resolve only when the test says so, which makes the race scenario deterministic.
- **Drafting the README and this file**, which I then reviewed and edited.

## One place where AI helped me move faster

The last-seat race test. The brief describes a specific interleaving (A starts paying, B starts paying, B finishes first, then A finishes). The AI put the payment provider behind a small interface and wrote a `ControlledProvider` for tests with a `settle(bookingId)` method, so the scenario became a plain sequential test with no timers and no flakiness: start A, start B, settle B → confirmed, settle A → refunded. The same seam made the "declined winner", "cancelled while the charge is in flight" and "expiry job must skip in-flight charges" tests one-liners, and a separate burst test (12 families, random provider latency) covers the timing-based variant.
